# Build 152 native Focus boundary and recovery

Status: **HOLD**. Private 1.0.66/build 152. Public build 142 is unchanged.
This repairs rollback, not successful Focus-compatible layout activation.

## Verified cause on the exact test OS

CPLCODEX01 runs macOS 27.0.1/26A434. A diagnostic process enumerated the actual
private framework through genuine Swift `CaseIterable` and `RawRepresentable`
witnesses. Its cases are exactly 0 through 8; no guessed ABI casts or integers
were used. The explicit complete list cannot exempt the observed Focus surface.

A bounded single-owner native probe compared baseline, complete explicit
allowlist with third-party restriction, Clock restriction, complete allowlist
again, and final deassertion. The owned fixture disappeared physically from
the menu row while Clock and Control Center remained; Focus disappeared under
the assertion and returned only after deassertion. Each terminal state required
three fresh consecutive observations. Final original inventory and both
physical fixture hits were restored. Product profile authority was not
requested. This is root-cause evidence, not product qualification.

Passing `nil` in a separate diagnostic hypothesis suppressed every system
control. That hypothesis was rejected and reverted. The private initializer
takes two nonoptional arrays and does not share the public assessment API's
nullable combined-allowlist contract. The production bridge preserves its
literal caller arrays.

Other maintainers document the same Focus limitation and provide replacement
controls, corroborating the probe without proving every macOS release behaves
identically. [Pelmet FAQ](https://github.com/fif7y/pelmet/blob/main/docs/FAQ.md).

## Conservative recovery repair

Build 151's failed transition planned compensation against reduced inventory,
then rejected the returning original Focus item as an unexpected addition.
Build 152 requires the original complete identity set to return before planning
compensation. One native deassertion is permitted only after an owned logical
mutation, with an all-visible original inventory and exactly one missing
strongly identified Apple/system-owned Focus item. Unknown losses, additions,
display changes, menu tracking and unrelated section or shelf edits are never
excused. A Focus change made externally during recovery is not overwritten.

Deassertion acknowledgement is not restoration proof. Two fresh complete,
stable observations are required. Incomplete recovery, changed return identity,
display relocation, external edits, configuration failure and deadline expiry
retain failure evidence and withhold layout authority. Existing uncancelled,
bounded compensation restores prior authority only after the original complete
target is verified. No phantom visible descriptors are inserted.

The native bridge also catches configuration-construction rejection or
exceptions without replacing its accepted assertion. Exact nine-case set
validation replaces a count-only check when deciding to clear the assertion.

## Source proof and remaining installed proof

The dirty fast gate passes 780 core tests and the native assertion transaction,
architecture, privacy, persistence, topology, packaging and repository checks.
New regressions cover recovery, missing return, wrong return ID/display,
unrelated edits, native configuration failure, forward cancellation and the
compensation deadline. The policy's negative matrix rejects ambiguous identity,
ownership, inventory and display states. Gemini and Astra found no source-bounded
P0/P1 in the narrow repair. Their review is not runtime or release approval.

Clean-source compilation, signed/notarized packaging and installed recovery
proof must bind to the newly frozen SHA and executable hashes. Successful
hidden-layout activation is still unqualified: its complete-inventory contract
does not yet model the observed platform-controlled Focus presence correctly.
That requires an explicit separate presence contract, not a broad missing-item
exception or retained phantom. The Focus access UX decision remains pending.

Existing release gates remain open: XCUITest runner initialization, actual
native clock-panel visibility, macOS 26 runtime, notched/multi-display hardware,
public-build Sparkle upgrade, and the remaining installed authority, recovery
and interaction matrix. Neither publication nor production signoff follows
from this document.
